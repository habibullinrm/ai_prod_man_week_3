# Страница-демо прототипа (Gate 3, блок C1)

Один самодостаточный HTML-файл: CSS, JS и данные встроены. Графики нарисованы вручную в SVG, внешних
библиотек нет; снаружи грузятся только шрифты Google Fonts.

## Как пересобрать

```bash
cd week_3
uv run python prototype/run_all.py           # ... -> plots -> export: пишет landing/data.json
uv run python landing/build_page.py          # template.html + data.json -> index.html, fragment.html
uv run python landing/check_page.py          # проверки раздела 8 + скриншоты в landing/screens/
```

Только страницу (без переобучения): `uv run python prototype/export_landing.py && uv run python landing/build_page.py`.
Playwright для проверок: `uv add --dev playwright && uv run playwright install chromium`.

| Файл | Что это |
|---|---|
| `template.html` | разметка, стили и скрипт страницы; данные подставляются вместо `__DATA__` |
| `data.json` | всё, что показывает страница (собирает `prototype/export_landing.py`) |
| `index.html` | полный документ для открытия локально |
| `fragment.html` | то же без `<!doctype>`/`<html>`/`<head>`/`<body>` — для публикации артефактом claude.ai |
| `check_page.py` | Playwright: 1280/390 px, светлая/тёмная тема, горизонтальная прокрутка, сеть, консоль, числа |

Ссылка на репозиторий прописана в `template.html` (раздел «Как воспроизвести»).

## Откуда числа

- Метрики и интервалы — из `prototype/reports/results.json` и `bootstrap.json`; `export_landing.py`,
  `build_page.py` и `check_page.py` сверяют их (assert).
- Продуктовая модель — `logreg_activity_grades` (логистическая регрессия на сплайнах). `export_landing.py`
  переобучает её той же фабрикой `common.MODELS[...]` на 2013 году и проверяет, что прогнозы совпадают
  с `test_scored.parquet`.
- Причины: вклад исходного признака = сумма `coef_j × (B_j(x) − mean_train B_j)` по его столбцам сплайн-базиса
  (и `_na`-индикатору). Сумма вкладов + сдвиг = логит модели (assert, допуск 1e-6). Показываются 3 признака
  с наибольшим положительным вкладом; `t` и `module_presentation_length` не выводятся. Признаки активности
  подписаны нейтрально («дней с заходами: 64»): модель нелинейная, и положительный вклад значит только
  «это значение повышает риск относительно среднего ученика», а не «мало».
- Демографии (gender, region, highest_education, imd_band, age_band, disability) и `final_result` в
  `data.json` нет (assert).

## Список куратора

Встроены три потока 2014 года разных модулей с наибольшим числом уходов: CCC 2014J (по умолчанию),
FFF 2014J, DDD 2014J. Места в списке считаются **внутри потока на день t** (так список видит куратор
потока). Главная метрика пайплайна ранжирует по всем потокам 2014 года сразу, поэтому «поймано X%»
в интерактиве — это доля внутри выбранного потока, а не главная метрика. Чтобы уложиться в размер,
в `data.json` лежат только ученики из топ-50% хотя бы одного из двух списков (максимальный бюджет
в интерфейсе — 50%); общая потеря снимка хранится отдельно.

## Правила отбора карточек

Кандидаты — снимки трёх встроенных потоков. Места и топ-N% — внутри потока на день t. Один ученик —
не больше одной карточки. Порядок выбора: тихий уход, явный уход, ложная тревога, ошибка.

| Случай | Правило | Кого берём из подходящих |
|---|---|---|
| Тихий уход | y=1; вне топ-20% правила; в топ-5% модели; n_missed ≥ 1 или score_drop < 0; days_to_leave ≥ 14 | наибольший риск модели |
| Явный уход | y=1; в топ-20% и правила, и модели | наибольший риск модели |
| Ложная тревога | y=0; в топ-5% модели; final_result ∈ {Pass, Distinction} | наибольший риск модели |
| Ошибка: уход без сигналов | y=1; вне топ-20% и правила, и модели; clicks_30 и score_mean в межквартильном диапазоне [25%; 75%] потока на тот же t; n_missed = 0 | **наименьший** риск модели |

Ничьи разрешаются по `enr`, затем по `t` — выбор детерминирован. `export_landing.py` проверяет, что каждая
карточка удовлетворяет своему правилу, а клики и «дни без заходов» в карточке, пересчитанные из исходного
`studentVle.csv` по дням < t, совпадают со снимком. Часть графика после t нарисована бледно и подписана
«модель этого не видела».

Отличия от задания: в случае «Ошибка» добавлено `n_missed = 0` и берётся наименьший риск (по решению
Рустама). С исходным правилом выбирался ученик на 21-м перцентиле с двумя пропусками, и он не подходил
под мысль «уход без сигналов».
