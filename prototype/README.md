# Прототип: предсказание оттока студентов (OULAD)

Задача: на каждом срезе `t = 30, 60, …, 210` день курса предсказать, что студент отчислится в следующие 30 дней.
Обучение на потоках 2013 года (2013B, 2013J), тест на 2014 (2014B, 2014J).
Из анализа исключены студенты, ушедшие до старта курса (`date_unregistration <= 0`, активности нет), и ушедшие без даты отчисления.

## Запуск

```bash
cd week_3
uv sync                                     # зависимости из pyproject.toml
uv run python prototype/run_all.py          # evaluate -> bootstrap -> plots (снапшоты берутся из кэша)
uv run python prototype/run_all.py --rebuild   # плюс пересборка снапшотов из data/oulad (~10 с)
```

Шаги можно запускать по отдельности: `build.py`, `evaluate.py`, `bootstrap.py`, `plots.py`.
Путь к данным по умолчанию `data/oulad`, можно переопределить переменной `OULAD_DIR`.

## Файлы

| Файл | Что делает |
|---|---|
| `common.py` | пути, константы (горизонт, бюджет топ-20%, цена), списки признаков, реестр моделей |
| `build.py` | снапшоты: популяция на дату `t`, метка, признаки активности и оценок только из дней `< t` → `snapshots.parquet` |
| `evaluate.py` | обучает модели, считает метрики на 2014 → `reports/results.json`, `reports/metrics.csv`, `test_scored.parquet` |
| `bootstrap.py` | 95% CI по студентам для доли пойманных потерь и прироста к правилу → `reports/bootstrap.json` |
| `plots.py` | графики → `reports/*.png` |

## Модели

| Имя | Что это |
|---|---|
| `baseline_7days` | правило «7+ дней без активности»; список сортируется по числу дней без активности |
| `lgbm_activity` | LightGBM только на признаках активности (клики, активные дни, дни с последнего клика, тренд) |
| `lgbm_activity_grades` | LightGBM на активности + оценках (сданные/пропущенные/просроченные задания, баллы) |
| `logreg_activity_grades` | логистическая регрессия на сплайн-признаках (GAM-подобная), те же признаки, что у предыдущей |

Модели ранжируют студентов по ожидаемой потере `p × оставшиеся платежи`.

## Метрики

- **Доля пойманных потерь, топ-20%** (главная, Gate 2 D3): команда удержания на каждом срезе обрабатывает 20% студентов; какая доля денег под риском попала в этот список.
- Recall, precision и lift в топ-20%, PR-AUC, ROC-AUC (по вероятности).
- Пойманные потери **при нагрузке правила**: модели берут столько же студентов, сколько флагует правило (~38%).
- Медиана дней до ухода у пойманных (сколько времени есть на удержание), калибровка, задержка предсказания.
